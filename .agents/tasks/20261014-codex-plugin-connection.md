# UserIO — проверка подключения плагина Codex

Прямое поручение пользователя 14 октября: отдельный исполнитель в проекте
UserIO должен разобраться с ошибкой подключения вызванного плагина @UserIO.
Делегировано корневой сессией Airlock; её маркетплейс и регистрации сюда не входят.

Владелец: `userio_connector_repair`. Границы: реальный hosted plugin →
`https://msg.bezrabotnyi.com/mcp` → UserIO, безопасная диагностика и минимальный
исправляющий срез, только если дефект воспроизводится. Чужой WIP сохранён.
Текущее состояние продукта: `.planning/STATE.md`, основной план фазы17:
`.planning/phases/17-telemost-chats-and-quiet-meeting-recording/17-01-PLAN.md`.
Эта проверка не меняет результат или объём фазы17.

## Результат

Доступ восстановлен без вмешательства исполнителя. Два настоящих вызова
`mcp__codex_apps__userio_userio_accounts_list` вернули `ok=true`, 16 аккаунтов;
нужные Gmail и SMS включены. Через тот же плагин чтение по одному новому
сообщению `mail` и `sms` также вернуло `ok=true`. Тексты сообщений не записывались,
прочтение не подтверждалось, никаких отправок не было.

Первичный `UNAVAILABLE / McpServerError: Connection failed / network_error`
получен корневой сессией. Точная причина этого единичного транспортного отказа
не установлена: повторить отказ не удалось. Это не доказанное исправление
кода и не основание менять GPTAdmin или здоровый UserIO.

Доказательства и точный следующий шаг при повторении:
`docs/verification/20261014-codex-plugin-connection.md`.
