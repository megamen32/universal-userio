# Matrix-мост для MAX и ВКонтакте через UserIO

[![Проверки моста](https://github.com/megamen32/universal-userio/actions/workflows/matrix-provider-bridge.yml/badge.svg)](https://github.com/megamen32/universal-userio/actions/workflows/matrix-provider-bridge.yml)

**Личные сообщения и группы MAX и VK в Matrix, с отправкой текста и вложений в обе стороны.**

Это Matrix Application Service: отдельный процесс связывает комнаты Matrix с аккаунтами,
которые уже подключены к [UserIO](https://github.com/megamen32/universal-userio).
UserIO хранит сессии мессенджеров и выполняет нативную отправку; мост отвечает за комнаты,
участников, вложения и обработку транзакций Matrix. Подключение через личные аккаунты
MAX и VK не является официальным продуктом этих компаний.

## Возможности и ограничения

| Возможность | Поддержка |
| --- | --- |
| Личные диалоги и группы | Отдельные комнаты в пространствах MAX и VK |
| Каналы | Исключены |
| Текст | В обе стороны; изменения своих текстовых сообщений |
| Изображения и файлы | В обе стороны, до 2 МиБ на вложение |
| Изображения MAX → Matrix | События `m.image` с настоящими байтами и `mxc://`, включая распознавание PNG/JPEG/GIF/WebP |
| Изображения Matrix → MAX | Передаются через файловый транспорт MAX |
| Несколько вложений в одном нативном сообщении | Передаётся первое вложение |
| Ответы Matrix | Отправляется текст ответа без служебной цитаты |
| История | Последние 10 сообщений при создании комнаты; до 200 сохранённых сообщений за проход |
| Сквозное шифрование | Не поддерживается; при включении комната приостанавливается |
| Реакции, звонки, синхронизация удаления, нативные ветки ответов | Не поддерживаются |

Выход из комнаты Matrix приостанавливает только её локальную синхронизацию.
Мост не выходит из группы MAX/VK и не удаляет переписку или контакт.
Возвращение в ту же комнату возобновляет синхронизацию.

Отправка считается подтверждённой только при наличии нативного идентификатора сообщения.
Повтор одной транзакции Matrix не создаёт новую отправку. Если исход неизвестен,
мост сохраняет ошибку и просит проверить исходный мессенджер перед ручным повтором.
Импортированные сообщения и вложения не отправляются обратно как новые сообщения.

## Требования

- Python 3.10 или новее. Сам мост использует только стандартную библиотеку.
- Рабочий UserIO с подключёнными личными аккаунтами MAX и/или VK и персональным токеном
  владельца. Нужны API списка и деталей бесед, отправки, загрузки и чтения байтов вложений:
  `/v1/conversations`, `/send`, `/uploads`, `/media/{message_id}/raw`.
  Используйте версию UserIO с поддержкой этого моста; произвольный старый сервер несовместим.
- Matrix homeserver с поддержкой Application Services, например Synapse,
  и доступ к его конфигурации.
- Matrix-аккаунт владельца и его токен доступа. Подключается один владелец на экземпляр моста.

## Установка на Linux с systemd

Сначала [разверните UserIO](../../docs/guide/self-host.md) и подключите
[MAX](../../docs/guide/max.md) и [VK](../../docs/guide/vk.md).
Убедитесь, что нужные беседы доступны в UserIO.

Из корня существующего checkout репозитория установите мост:

```bash
sudo useradd --system --home-dir /var/lib/userio-matrix-bridge --shell /usr/sbin/nologin userio-matrix-bridge
sudo install -d -m 0755 /opt/userio-matrix-bridge
sudo install -d -o userio-matrix-bridge -g userio-matrix-bridge -m 0700 /var/lib/userio-matrix-bridge
sudo install -m 0644 deploy/matrix-provider-bridge/bridge.py /opt/userio-matrix-bridge/bridge.py
sudo install -o userio-matrix-bridge -g userio-matrix-bridge -m 0600 deploy/matrix-provider-bridge/config.example.json /var/lib/userio-matrix-bridge/config.json
sudo install -m 0644 deploy/matrix-provider-bridge/userio-matrix-bridge.service /etc/systemd/system/
```

Если системный пользователь уже существует, пропустите `useradd`.

1. Заполните приватный `config.json` по [примеру](config.example.json).
   `owner_mxid` и `server_name` должны принадлежать одному homeserver.
   `owner_token` — Matrix-токен этого владельца; `userio_token` — его персональный
   токен UserIO; `userio_user_id` — точный внутренний ID пользователя UserIO.
   В `accounts` укажите существующие `account_ref` из UserIO, а не произвольные названия.
   Ненужный провайдер удалите; `excluded_peers` содержит нативные ID исключённых бесед.
2. Создайте приватную копию [registration.example.yaml](registration.example.yaml).
   Сгенерируйте два разных случайных токена, например через Python `secrets.token_hex(32)`.
   Значения `as_token` и `hs_token` должны совпадать в регистрации и конфигурации моста.
   Замените `example.org` в регулярных выражениях на свой домен, экранируя точки.
   Не меняйте префикс `_userio_`: он используется исходниками.
3. Укажите в регистрации `url`, доступный homeserver, а в конфигурации — доступный
   мосту `homeserver`. Значения localhost подходят только для процессов на одном хосте.
   Для разных хостов или контейнеров настройте явные адреса и `bind`; порт по умолчанию 18097.
4. Передайте регистрационный файл Synapse через `app_service_config_files`:
   ```yaml
   app_service_config_files:
     - /etc/matrix-synapse/userio-provider-bridge-registration.yaml
   ```
   Сохраните остальные регистрации. Файл должен читаться пользователем Synapse и
   не быть доступен посторонним. Перезапустите homeserver штатным способом.
5. По умолчанию unit требует `universal-userio.service` на том же хосте.
   Если UserIO удалённый или имя unit другое, адаптируйте `After` и `Requires`.
   Затем запустите мост:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now userio-matrix-bridge
   sudo systemctl status userio-matrix-bridge
   curl --fail http://127.0.0.1:18097/health
   ```
6. В Matrix примите приглашения в пространства MAX/VK и комнаты бесед.
   Проверяйте первую отправку в переписке с собой и сравните её с исходным мессенджером.

Токены, регистрацию с настоящими секретами, SQLite и переписки храните вне Git.
`owner_token` необязателен для части операций API, но нужен для штатной привязки владельца;
для полной установки заполните его. Обычные Matrix-чаты мост не перенастраивает.

## Эксплуатация

Unit содержит конечный бюджет: RAM 96/192 МиБ (soft/hard), swap 0, CPU 50% одного ядра,
32 задачи, 128 файловых дескрипторов, IOWeight 25. Это стартовый бюджет данного процесса;
перед установкой проверьте резерв своего хоста и ограничения UserIO.
Вложения обрабатываются последовательно в памяти, SQLite ограничена 512 МиБ,
целевой размер журнала — 8 МиБ. Планируйте место для базы, WAL и резервной копии отдельно.

`/health` показывает свежесть опроса, число комнат, ожидающих и ошибочных отправок.
Просмотр журнала: `sudo journalctl -u userio-matrix-bridge -n 50`.
При сбое не удаляйте базу: она хранит привязки комнат и защиту от повторной отправки.
Для резервной копии остановите мост или используйте SQLite backup API.

Остановка: `sudo systemctl stop userio-matrix-bridge`.
Сохраните конфигурацию и базу; удалять комнаты или выходить из мессенджеров не требуется.
При штатной остановке регистрация остаётся у Synapse для последующей доставки транзакций.

## Проверка и участие

```bash
cd deploy/matrix-provider-bridge
python3 -m unittest -v test_bridge
```

Категория: fast unit; ожидаемое время 10 секунд, максимум 30 секунд.
Проверяются изоляция аккаунтов и автора, идемпотентность, неясный исход отправки,
leave/rejoin, редактирование и отсутствие дублей после импорта вложений.
GitHub Actions выполняет эти проверки на Python 3.10 и 3.12 в одном job с общим
лимитом 180 секунд, включая подготовку. Каждый прогон ограничен 30 секундами,
RAM 96/192 МиБ, swap 0, CPU 50%, Tasks 32, IOWeight 25, 128 дескрипторами
и размером отдельного временного файла 16 МиБ.

Focused integration: текст, PNG и файл в обе стороны для обоих провайдеров,
проверка нативного подтверждения и повтора транзакции; ожидаемое время 90 секунд,
максимум 180 секунд с подготовкой. Последняя проверка живых аккаунтов 14.10.2026:
12 из 12 сценариев успешны. Такие проверки требуют личных сессий и не запускаются
в публичном CI. Slow nightly для этого компонента не предусмотрен.
