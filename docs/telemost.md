# Телемост: запись встречи по ссылке

Телемост — один из каналов универсального UserIO, наряду с Telegram, Matrix
и сотовой связью. Описанная возможность относится к встречам/записи и не
обещает произвольный исходящий звонок или разговор ИИ через опубликованный
микрофон. Notice Place может использовать только реально объявленные
возможности канала. AgentCall, Asterisk и GSM2SIP не являются обязательным
маршрутом встречи Телемоста. [Архитектура](COMMUNICATIONS-ARCHITECTURE.md).

Размещение recorder сверяется с [контейнерной установкой](container-deployment.md).
Ниже сохранены параметры прежнего размещения на server-44; это историческая
инструкция, не команда возвращать процесс с UserIO Voice на старый хост.

Автоматическое подключение и запись проверены на живой встрече: получены голос,
WAV и расшифровка; воспроизведение, скачивание и обновление страницы подтверждены.
Автозапуск по новой ссылке из Telegram Секретаря тоже проверен: он сам вошёл,
записал голос, сохранил WAV и расшифровку. Распределение голосов по именам и
долгий многочасовой запуск пока не прошли отдельную приёмку.

## Через Секретаря

Пришлите Секретарю одну ссылку на встречу Телемоста. Для подключённого владельца
запись запускается сразу, без ожидания ответа модели или дополнительного вопроса.
Секретарь отвечает ссылкой на запись в UserIO. По умолчанию предел — один час;
организатор может потребовать допуск. Для остановки попросите Секретаря остановить
запись либо нажмите «Остановить запись» на странице встречи в UserIO.

Сообщения «не записывай» или «не подключайся» не запускают запись. Обычная
переписка продолжает работать. Автозапуск предназначен для владельца подключённого
UserIO, а не для произвольного участника группы. Подключение записи использует
отдельный MCP-ресурс `userio_meetings` с персональным scope `meeting_recording`:
только начать, прочитать и остановить собственную запись. Токен чтения сообщений
менять не нужно; значение токена хранится штатно в зашифрованном ресурсе Airlock.

## Через сайт

Откройте [Встречи](https://msg.bezrabotnyi.com/telemost), войдя в свой UserIO.
Укажите ссылку `https://telemost.yandex.ru/j/…`, длительность и нажмите
«Подключиться и записывать». Участник «Секретарь · запись встречи» виден другим,
микрофон, камера и публикация медиадорожек выключены. Организатор может потребовать
допуск; ожидание можно отменить. Ошибку/неизвестный результат нельзя исправлять
повторной отправкой того же внешнего действия под новым request_id.

Интерфейс: `userio.meetings.telemost.start/get/stop` и
`POST /v1/meetings/telemost`, `GET /v1/meetings/telemost/{id}`,
`POST /v1/meetings/telemost/{id}/stop`. Персональный readonly остаётся readonly.
MCP start: `url`, уникальный `request_id`, `max_seconds`30–7200.
Один явный вызов подключает видимого участника с выключенными микрофоном и камерой;
отдельное подтверждение не требуется. Принятый или неизвестный вход не повторяется.
Идентификатор сохраняется до соединения. Запись и расшифровка доступны только
владельцу. API аудио поддерживает Range и ограниченное потоковое чтение.

Транспорт использует схему connection/hello/subscriberSdpOffer из
[WhiteTransport](https://github.com/meanwebuser/whitetransport), отдельно от его
DataTunnel/VPN. Нативный RTC receiver первоначально размещался на44;
контейнерная поставка переносит исполнение в UserIO Voice. Фактическое
размещение проверяется перед запуском; отдельный браузер и копирование
учётных записей Yandex/WhiteTransport для этого маршрута не требуются. Вход гостевой;
закрытая для гостей встреча может отказать. Прямое опубликованное API360
организаций не является API записи аудио личного аккаунта.

Аудиопотоки сохраняются как mono16kHzPCM WAV с SHA; после окончания автоматически
разбираются существующим Whisper. Имена участников не угадываются по номеру
дорожки. Whisper запрашивается с `diarize=true` и `response_format=verbose_json`:
сохраняются исходные segments, speaker_turns и анонимные метки. Каждая
120-секундная порция имеет свой speaker_scope; одинаковые метки разных порций
не доказывают одного человека. Это разделение речи, а не установление личности.
Исходный текст с метками появляется сообщениями в том же чате встречи,
доступном обычным чтением истории владельца. Постоянные message IDs предотвращают
дубли проекции. Отказ диаризации сохраняет аудио и явную ошибку расшифровки.
Задержки включения дорожек отражены в `started_offset`. Неуспех расшифровки не удаляет аудио.

Личные и групповые чаты Яндекса подключаются отдельно от гостевой записи
встречи. Для уже подключённого аккаунта проверены чтение, постоянная
синхронизация, текстовая отправка и сохранение сообщения после обновления.
Самостоятельное подключение произвольного нового Яндекс-аккаунта и богатые
действия ещё не прошли приёмку. Обычная автоматическая запись/транскрипция
прошла живую приёмку; оставшиеся требования см. фазу17 GSD.

## Historical runtime profile (server-44)

`deploy/userio-telemost.service`: private Unix socket на44, one meeting,
RAM1/2GiB, swap0, CPU2, tasks128, IOWeight10, максимум2часа/8audio streams/
2GiB per recording, archive admission8GiB +22GiB free disk. Publisher согласуется без локальных аудио/видеотреков.
Пакеты aiortc1.14.0, aiohttp3.13.3. Конфигурация100:
`USERIO_TELEMOST_SSH_HOST=192.168.2.5`; SSH через существующий пользовательский
ключ roomhacker. Сам рабочий процесс не принимает произвольные shell-команды.
Данные0700/0600, никаких cookies/secrets в Git. Глобальные модели, аккаунты,
SIP и Telegram transport не меняются.


Приёмка диаризации16октября: реальная2159.699с запись,18фрагментов,
604сегмента; исходныйWAV не изменился. Все18текстов перечитаны точным
message_id через прежний штатный инструмент Секретаря; история содержит
ровно18частей без дублей. Автоматическая сводка/публикация любых будущих
встреч отдельным расписанием не добавлялась.
