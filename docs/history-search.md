# Поиск по истории: текст и смысл

Поиск в боковой панели ищет чаты и отдельные сообщения всей сохранённой
доступной истории. Результат показывает автора, время и ссылку на оригинал.
Ссылка открывает точное сообщение, даже если оно старше последней страницы.

В настройках «Смысловой поиск по истории» можно включить свою коллекцию Qdrant:
указать URL, collection и при необходимости ключ, затем совместимый embeddings
endpoint, модель, размерность и ключ. Секреты обратно не показываются. Без
настройки или при отказе сервера работает текстовый поиск; фактический режим
и неполное покрытие видны явно.

Один ограниченный фоновый worker постепенно обрабатывает историю, начиная с
рабочих чатов, и подхватывает изменения. Перезапуск продолжает работу; неизменный
текст повторно не векторизуется. В Qdrant — векторы, координаты и hash, оригинал
остаётся в SQLite. Перед выдачей проверяются актуальный текст, удаление, аккаунт
и право чтения. Каждый пользователь использует только свои настройки и данные.
Qwen3-Embedding получает инструкцию задачи только для запроса; документы сырые.

Web, HTTP и агенты используют одно ядро. Существующий `userio.channels.list`
принимает `search`, `scope=message`, `mode=text|semantic|hybrid`, точные
`conversation_ids`, `account_ref`, `limit`, `offset`. Без `search` это прежний
список чатов. HTTP: `/v1/search`, `/v1/search/settings`, `/v1/search/index`.
Результат: `results`, `mode_used`, `semantic`, `coverage`; полнота выбранного
набора чатов отличается от полноты всего архива. У X-manager поиск ограничен
его действующими рабочими источниками, а не всем личным inbox владельца.

Агенту нужен отдельный поисковый инструмент, а не поиск внутри списка чатов.
`userio.channels.search` даёт три входа и одно ядро: `query` ищет по имени
чата, контакта и тексту сообщения, `conversation_id` и `message_id` находят
объект по точному идентификатору — по живой базе, поэтому чат, который не
попал в текстовый индекс, всё равно находится. Строки читаются из
`structuredContent.results`: для чатов это `id`, `display_name`, `preview`,
для сообщений — `conversation_id`, `message_id` и `deep_link`. Формат тот же,
что у веб-поиска, поэтому сайт и агент видят одинаковый результат.
