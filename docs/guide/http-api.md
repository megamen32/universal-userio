# HTTP API

## Авторизация

Персональный API-вход выполняется через `POST /auth/login` с именем пользователя и паролем. Полученный bearer-токен ограничен этим пользователем. Для ИИ-клиентов предпочтителен OAuth.

Серверный service-account токен не предназначен для браузера или пользовательского приложения. Не вставляйте его в примеры, URL, HTML, логи или сообщения ИИ.

## Вход по одноразовому коду

Пароль можно заменить одноразовым кодом: по email он приходит от сервисного ящика, по Telegram подтверждается самим Telegram.

| Метод и путь | Назначение |
| --- | --- |
| `POST /auth/challenge` | Запрос кода на email: `{"destination": "..."}`. Ответ всегда `202 {"status":"accepted"}` — одинаковый для известных и неизвестных адресов |
| `POST /auth/login/code` | Обмен кода на bearer-токен: `{"destination": "...", "code": "123456"}` |
| `POST /auth/session/code` | Вход в кабинет по коду (форма), выставляет сессионную cookie |
| `POST /auth/telegram` | Вход по подписи Telegram Login Widget |

Код действует 10 минут, срабатывает один раз и не более пяти попыток. На один адрес — не больше трёх запросов за 15 минут, на клиент — десять за час.

## Маршруты для чтения

| Метод и путь | Результат |
| --- | --- |
| `GET /v1/accounts` | Подключённые аккаунты текущего пользователя |
| `GET /v1/conversations` | Список его диалогов |
| `GET /v1/conversations/{id}` | История и состояние выбранного диалога |
| `GET /v1/inbox` | Непрочитанные сообщения |
| `GET /v1/drafts/pending` | Ожидающие черновики |
| `GET /v1/runtime` | Идентификация развёрнутой версии |

## Маршруты изменения состояния

| Метод и путь | Назначение |
| --- | --- |
| `POST /v1/messages` | Приём нормализованного сообщения по настроенному маршруту |
| `POST /v1/conversations/{id}/drafts` | Создание текстового черновика |
| `PATCH /v1/drafts/{id}` | Изменение сохранённого черновика |
| `POST /v1/drafts/{id}/approve` | Действие доставки выбранного черновика |
| `POST /v1/inbox/seen` | Явное изменение локального статуса прочитанного |
| `POST /v1/sms/device-connect` | Подключить свой Android с отдельным device token |
| `POST /v1/imap/accounts`, `/v1/matrix/accounts` | Подключить свой ящик/Matrix для чтения |

HTTP-метод `approve` уже означает действие. Не вызывайте его для предпросмотра и не полагайтесь на то, что подтверждение MCP автоматически защищает вашу собственную REST-интеграцию. Проверку согласия пользователя нужно сохранить и в клиенте.

## Минимальная проверка доступа

В репозитории есть пример `examples/userio/read_accounts.py`: он запрашивает персональные учётные данные локально, получает токен в памяти и читает список аккаунтов. Пример не отправляет сообщения и не печатает токен.

```bash
python examples/userio/read_accounts.py
```

## События рабочего процесса

`GET /v1/workspace/events` предоставляет ленту с курсором в области текущего пользователя. Воркеры должны сохранять курсор и применять ограничения аккаунтов и чатов. Повторная обработка не должна приводить к повторной отправке.

Наличие сообщения в User.io и окончание агентного разбора являются разными этапами. Сохраняйте их состояния раздельно.

## Ошибки и повторы

`401`: нет действующей авторизации. `403`: не хватает прав. Остальные ошибки разбирайте по телу ответа и контракту конкретного маршрута.

Чтение можно повторять с ограниченной задержкой. Не повторяйте отправку вслепую после сетевого тайм-аута: результат у провайдера может быть уже принят.

## Права отдельных токенов

В `/connect-mcp` выберите «Выбранные аккаунты и чаты»: платформы сгруппированы,
для каждого аккаунта доступны чтение либо чтение и запись, все чаты либо явный
список. В списке чатов можно назначить разные права. «Настроить права» изменяет
действующий токен после сохранения, без выдачи нового значения.

`POST /v1/personal-tokens` принимает `scope: scoped_messenger` и `grants`:
`[{account_ref, access: read_only|read_write, chats: null|[{conversation_id, access}]}]`.
`POST /v1/personal-tokens/{id}/permissions` сохраняет тот же `grants`.
Не выбранные аккаунты/чаты недоступны. Этот токен предоставляет generic
`userio.messenger.*` и ограниченный `userio.accounts.list`; широкие legacy
инструменты, настройки, личная память и сторонние операции недоступны.
Права проверяются до провайдера; запись по-прежнему требует точного одобрения.
