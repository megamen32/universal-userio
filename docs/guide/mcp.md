# MCP: инструменты и вызовы

## Транспорт

Текущая редакция MCP — `2026-07-28`. UserIO принимает её современный stateless-формат и сохраняет старый handshake `2024-11-05` для совместимых клиентов. Для начала клиент может вызвать `server/discover`; каждый современный запрос содержит `_meta.io.modelcontextprotocol/protocolVersion` и `_meta.io.modelcontextprotocol/clientCapabilities`.

Удалённый сервер расположен на `/mcp`. Для опубликованного сервиса используйте HTTPS и OAuth либо персональный Bearer-токен. Современный HTTP-клиент отправляет `MCP-Protocol-Version`, `Mcp-Method` и, для `tools/call`/`resources/read`, `Mcp-Name`; тело и заголовки должны совпадать. Клиент указывает поддержку `application/json` и `text/event-stream`; UserIO отвечает одним из этих форматов.

Локальный stdio-режим запускается отдельно:

```bash
python -m universal_userio
```

Это запуск локального MCP-сервера, а не автоматическое подключение к вашему аккаунту на публичном User.io.

## Обнаружение и схемы

Современный клиент может сначала узнать редакции протокола и возможности сервера:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "server/discover",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}
```

Затем получите список инструментов с тем же `_meta` в `params`. Для каждого инструмента используйте `inputSchema` установленной версии и проверяйте обязательные поля; не добавляйте аргументы по аналогии с другим каналом.

## Пример чтения списка Telegram-чатов

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "userio.channels.list",
    "arguments": {"channel": "telegram"},
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}
```

При `userio.channels.read` MCP возвращает вложенные изображения как стандартные image content blocks по умолчанию; передайте `include_images: false`, чтобы отказаться от байтов изображения. Для голосовых `media_delivery` показывает состояние распознавания и наличие транскрипции в тексте. Сырые голосовые байты этим инструментом модели не передаются.

Для получения целого Telegram/MAX-вложения передайте в `userio.channels.download`
его `file_ref`; для нескольких вложений того же сообщения укажите точный
`attachment_index` (0–7). По умолчанию результат содержит имя, MIME, длину,
SHA-256 и исходные байты в base64. `mode: "mcp_resource"` добавляет оригинал
как MCP resource и, где доступно, извлечённый текст. Входом служит только
сообщение из привязанного аккаунта/чата; произвольные URL не принимаются.
MCP-передача ограничена 4 МиБ, загрузка файлов MAX — 2 МиБ.

`userio.messenger.media` также принимает точные `account_ref`,
`conversation_id`, `message_id` и `attachment_index`; для файлов возвращает
оригинальные байты, имя, MIME, размер и SHA-256 без отметки сообщения как
прочитанного. UI чата показывает отдельную кнопку скачивания для каждого
поддерживаемого вложения и сверяет полученные размер и SHA-256 перед сохранением.

Для документов `mcp_resource` сохраняет прежнюю обработку: текстовые файлы
читаются напрямую, PDF/Office/OpenDocument/RTF/EPUB извлекаются Firecrawl AnyDoc,
а оригинал остаётся в resource-блоке. Для видео возвращаются выбранные кадры и
транскрипция через настроенный Whisper. `include_images: false` исключает
изображения и кадры из контента для модели; для ручной выгрузки используйте
base64-режим и оставьте включёнными исходные bytes.

Внутренний AI-обработчик UserIO также подгружает ограниченные изображения в vision-модель; по умолчанию это `MiniMax-M3.1-Flash`, настраиваемая через `USERIO_AI_IMAGE_MODEL`.

## Основные группы

| Инструмент или группа | Назначение |
| --- | --- |
| `userio.channels.list` | Доступные чаты канала |
| `userio.channels.search` | Поиск чатов и переписки по имени, тексту, id чата или id сообщения |
| `userio.channels.export` | Выгрузка всего чата в один Markdown-файл: авторы, голосовые с расшифровкой, ответы; медиа — по флагу |
| `userio.channels.read` | Чтение переписки |
| `userio.channels.download` | Получение поддерживаемых вложений |
| `userio.messages.prepare` | Один черновик для готового чата или нового контакта; ничего не отправляет |
| `userio.contacts.resolve` | Резолв контакта, которого ещё нет в истории, в peer провайдера |
| `userio.draft.approve_send` | Подтверждение и отправка точного черновика |
| `userio.messenger.button_click` | Нажать точную видимую callback-кнопку в принадлежащем аккаунту сообщении Telegram; итог и UNKNOWN сверяются по `request_id` |
| `userio.messenger.telegram_admin.propose` | Предложение создать группу/канал или изменить участников Telegram; исполнение только через отдельное подтверждение |
| `userio.workspace.policy.*` | Политика автоматической обработки |
| `userio.workspace.poll` | События для обработчика с явным курсором |
| `userio.workspace.triage.*` | Настройки разбора и обратная связь |

Таблица является навигатором по инструментам. Полная схема параметров берётся через `tools/list`.
Правила callback-кнопок, сверки сообщения и запрета повторного UNKNOWN описаны в
[контракте действий Messenger](../messenger-contract.md#telegram-inline-callback-buttons).

## Новый контакт: начать переписку

Инструменты `userio.channels.*` работают с чатами, которые уже есть в истории.
Для готового чата и нового контакта используется один инструмент подготовки:

- `userio.contacts.resolve` — превращает идентификатор в peer провайдера (ник
  Telegram, номер телефона, адрес почты, профиль VK, идентификатор Яндекса).
  Ничего не отправляет и ничего не пишет собеседнику.
- `userio.messages.prepare` — принимает `conversation_id` либо `account_ref` и
  `identifier`, разрешает нового получателя и сохраняет обычный черновик.
  Отправка выполняется только через `userio.draft.approve_send`.

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "userio.messages.prepare",
    "arguments": {
      "account_ref": "telegram:540308572",
      "identifier": "@vampsupport_vpn",
      "text": "Привет! Это первое сообщение.",
      "request_id": "message-prepare-20261023-01"
    }
  }
}
```

`request_id` делает повтор идемпотентным: тот же запрос вернёт тот же черновик без
отправки. Для отправки подтвердите точный текст, чат и вложения черновика. Ответ собеседника приходит в этот же чат — UserIO
создаёт беседу под тем же ключом, который вычислит входящее сообщение.

Что работает по каналам и где границы — в разделе [«Начать переписку с новым
контактом»](channels.md#начать-переписку-с-новым-контактом).

Персональный read-only токен не резолвит контакты и не начинает переписку.
Скоуп-токен может начать её только аккаунтом, выданным целиком, и только с
правом `read_write`: токен, ограниченный списком готовых чатов, новый чат
открыть не может.

## Голосовые вызовы и встречи

UserIO включает каналы звонков Telegram и MatrixRTC, встречи Телемоста и
отдельно настроенную SIM-телефонию. Это разные account-scoped возможности.
Установленные `tools/list` и capabilities — источник точных имён и аргументов;
не переносите схему одного канала на другой. Наличие канала чтения не даёт права
позвонить или записать встречу.

Для обращения агента к оператору используйте API/MCP Notice Place; он отвечает
за вопрос, расписание и эскалацию, а UserIO исполняет разрешённый транспорт.
Обычные сообщения и чтение остаются в UserIO. Начало вызова не означает ответ,
а голосовой ответ не равен подтверждённому решению. [Архитектура](architecture.md).

## Ошибки

Проверяйте и JSON-RPC `error`, и `result.isError`. Успешный HTTP-статус сам по себе не доказывает успех инструмента.

`not supported by adapter` означает, что операция недоступна этому адаптеру. Нельзя молча заменять её другим действием, например удалять сообщение у провайдера вместо удаления локальной копии.

## Подтверждение отправки

Вызов отправки должен относиться к конкретному сохранённому черновику с явным `confirm: true`. Проверьте остальные обязательные поля в схеме. Редактирование текста после согласования требует нового подтверждения.

Повтор при неизвестном результате доставки может создать дубликат. Сначала сверяйте сохранённый результат и исходный чат.

## Группы и каналы Telegram

В обычном токене «Выбранные аккаунты и чаты» включите право «Управлять группами
и каналами» у конкретного Telegram-аккаунта. Создание требует прав на весь
аккаунт; приглашение, исключение и удаление канала проверяются по разрешённым
чатам этого же токена. ИИ вызывает `userio.messenger.telegram_admin.propose`,
показывает сформированный UserIO план, затем владелец подтверждает тот же `action_id` и
`hash` через `userio.messenger.approve`.

Группа — общий чат; супергруппу Telegram представляет как megagroup-канал.
Broadcast-канал предназначен для публикаций; новые каналы создаются приватными.
Исключить участника из супергруппы означает забанить его, поэтому запрос требует
`ban_on_supergroup: true` и не снимает бан автоматически. Удаление канала
необратимо и доступно только когда выбранный аккаунт сейчас его создатель;
подтверждение должно содержать `DELETE CHANNEL <peer_id>`. Выход из канала не
подменяет его удаление. При неизвестном исходе повтор того же admin-подтверждения
вернёт сохранённый результат или `unknown`, но не повторит TL-операцию.

## Новые документы от агента

Агент может подготовить новый файл через `userio.messenger.upload`, затем
предложить обычное действие `file` с полученным `upload_id`. Отправка требует
подтверждения точного действия. Сначала агент проверяет capabilities выбранного
аккаунта: `file` и `file_upload` должны быть разрешены. Приватный токен только
для чтения не получает права на отправку.

Лимит нового файла — 2 МиБ. UserIO привязывает его к конкретному диалогу и
исходному сообщению, проверяет содержимое по SHA-256 и сохраняет результат
отправки. Доставка новых байтов через MAX проверена; интеграция экспорта
документов в самом Секретаре проходит отдельную приёмку.
