# Сопровождение документации User.io

## Структура

- `docs/guide/*.md`: исходный текст руководства; читается прямо в GitHub.
- `docs/guide/navigation.json`: порядок, названия, группы и ссылки на источники.
- `docs/index.html`: собранный автономный сайт для GitHub/локального просмотра.
- `src/universal_userio/static/docs.html`: тот же сайт в обычном runtime-release.
- `docs/README.md`: оглавление для GitHub.
- `tools/userio_docs/`: сборщик, стили и скрипт интерфейса.
- `examples/userio/read_accounts.py`: проверка персонального API-доступа без отправки сообщений.

Сайт не использует внешние шрифты, JavaScript-библиотеки, трекеры или сетевые запросы для поиска. Поиск работает по всем статьям, примерам и справке. Интерфейс поддерживает мобильное меню, светлую/тёмную тему, переходы по разделам, копирование примеров и Markdown, клавиатуру и печать текущей статьи.

## Пересобрать

Сборщик требует Python 3.10+ и `markdown-it-py`. Эти зависимости относятся только к документации; их не требуется добавлять в production-окружение User.io.

```bash
python3 -m venv .venv-docs
. .venv-docs/bin/activate
python -m pip install -r tools/userio_docs/requirements.txt
python tools/userio_docs/build.py
python tools/userio_docs/check.py
```

Локально открывайте `docs/index.html` обычным браузером. При ограничениях на `file://` можно использовать локальный статический сервер:

```bash
python -m http.server 8080 --bind 127.0.0.1 --directory docs
```

Откройте `http://127.0.0.1:8080/`. Команда не публикует сайт в интернете.

## Добавить статью

Создайте Markdown-файл в `docs/guide/` с одним заголовком первого уровня. Добавьте его в `navigation.json` и ссылки из соседних статей. Внутренние ссылки в Markdown имеют вид `[Telegram](telegram.md)`; сборщик превращает их в маршруты сайта. Заголовки второго уровня формируют оглавление справа.

После изменения текста пересоберите `docs/index.html` и запустите проверки. Добавляйте ссылки на конкретные исходники для технических контрактов. Не копируйте секреты, переписки или содержимое окружения.

Для пользовательского текста: конкретное действие, результат проверки, решение типичной ошибки. Не добавляйте рекламные превосходные степени и метакомментарии о том, как написана инструкция.

## GitHub Pages

В настройках репозитория откройте **Settings → Pages → Build and deployment**. Выберите **Deploy from a branch**, ветку `main` и папку `/docs`, затем сохраните.

В `docs/index.html` уже находится готовый HTML; `.nojekyll` исключает обработку Jekyll. Отдельная тяжёлая сборка Node.js не нужна. GitHub всё равно выполняет собственный процесс публикации Pages; этот пакет не отключает и не меняет другие workflows проекта.

Перед выбором `/docs` проверьте уже существующие файлы этой папки: на Pages они могут быть доступны публично, а не только через оглавление. Не публикуйте приватные заметки. Источник настройки: [GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Публикация на домене UserIO

Штатный HTTP runtime отдаёт только готовый файл документации по `/docs/`,
`/docs` и `/docs/index.html`. Сборщик обновляет обе копии; `check.py` проверяет
равенство и воспроизводимость. Публикуйте через обычный source commit/push и
rollback-first `scripts/runtime_release.py`. Отдельный nginx-route, daemon
или npm-build не нужен. Весь каталог репозитория `docs/` не публикуется.

После установки проверьте `/docs/` без входа, поиск, мобильное меню и ссылки
на кабинет. `/v1/accounts`, `/v1/inbox` и `/mcp` сохраняют авторизацию.
Лендинг и телефонная инструкция содержат ссылку на опубликованный `/docs/`.

## Ссылка из README и лендинга

В основной README репозитория добавьте:

```markdown
## Документация

[Быстрый старт](docs/guide/quickstart.md) · [Каналы](docs/guide/channels.md) · [MCP и API](docs/guide/mcp.md) · [Все инструкции](docs/README.md)
```

После фактической публикации добавьте пункт **Документация** в верхнее меню лендинга и ссылку в футер. Путь должен вести на работающий адрес `/docs/` или Pages. Не добавляйте публичную ссылку на ещё не опубликованный сайт.

## Проверка на реальном сайте

Используйте обычный управляемый браузер и только свою вкладку. Проверьте
лендинг → документация → поиск → телефонная статья → API, тёмную тему и
мобильное меню; сохраните снимки. Это реальная приёмка, в отличие от
скриншотов `set_content` старого пакета.

Опциональный `browser_check.py` подключается к уже запущенному CDP и требует
точный ID вашей вкладки, уже открытой на `/docs/`. Установите Playwright
только в среде проверки; браузер или его бинарники script не скачивает,
новые вкладки не создаёт, общий браузер не закрывает. Соблюдайте своё
обычное окно ресурсов. Результаты по умолчанию идут в ignored `.tmp/docs-browser`.

```bash
python tools/userio_docs/browser_check.py \
  --cdp-url http://127.0.0.1:9223 --target-id YOUR_OWN_TARGET_ID
```
